# Sanity i18n Migration Plan

The marketing frontend already passes a `$locale` parameter to every
GROQ query and falls back to English when no localized document
exists. The Sanity Studio itself stays single-locale until we're ready
to translate content.

## When to migrate

Trigger this plan once a product decision lands to ship Russian (or any
other locale) marketing content. Until then the cost is zero — the `en`
documents work as they always have.

## Steps

1. **Install the plugin** (in this workspace):
   ```sh
   npm install @sanity/document-internationalization
   ```

2. **Wire it in `sanity.config.ts`**, applied to the three document
   types:
   ```ts
   import {documentInternationalization} from '@sanity/document-internationalization'

   plugins: [
     structureTool({structure}),
     documentInternationalization({
       supportedLanguages: [
         {id: 'en', title: 'English'},
         {id: 'ru', title: 'Russian'},
       ],
       schemaTypes: ['landingPage', 'siteSettings', 'supportPage'],
     }),
     visionTool(),
   ],
   ```
   Drop the fixed singleton IDs and rebuild the structure so each locale
   appears as its own list item. The plugin generates per-locale
   document IDs (e.g. `siteSettings__i18n_ru`).

3. **Backfill existing documents**:
   ```groq
   *[_type in ["landingPage", "siteSettings", "supportPage"] && !defined(language)]
   ```
   For each hit, patch `language = "en"` and let the plugin create the
   `translationMetadata` pointer. Do this on a cloned dataset first,
   verify the current Next.js build renders identically, then apply to
   `production`.

4. **Object/section schemas** (`heroSection`, `bentoFeaturesSection`,
   `ctaSection`, `ctaBlock`, `link`, `seo`) do not need the plugin —
   they are embedded inside localized parent documents and inherit the
   parent's locale automatically.

5. **Frontend** — no change required. `apps/marketing/lib/sanity/queries.ts`
   already accepts a locale parameter and falls back to English.

6. **Sitemap + hreflang** — once at least one translated document
   exists, update `apps/marketing/app/sitemap.ts` to emit
   `alternates.languages` entries for the URLs that have translations,
   and set `x-default` to English.

## Rollback

Uninstalling the plugin leaves the `language` field on the documents
(which `coalesce(language, "en")` tolerates) but restores the original
structure builder. Dropping the field across all docs is optional
cleanup.
