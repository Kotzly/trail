## Design Context

### Users

Trail's two primary audiences are **deep-research analysts** (journalists, academics, due-diligence) and **builders/engineers** (devs, PMs investigating bugs, comparing libraries, reading docs). Both run long browser sessions across dozens of tabs, fork constantly, and need to retrace exactly how they got somewhere. They expect power-user density, keyboard-driven flow, no hand-holding, and zero novelty for novelty's sake. They will leave instantly if something feels like a generic SaaS dashboard.

The job-to-be-done is "show me the actual shape of my research, so I can pick up any thread without rebuilding context from scratch."

### Brand Personality

**Cinematic. Editorial. Organic.**

- *Cinematic* — narrative pacing, scroll-driven reveals, single hero moments instead of a wall of features. The landing already runs a 5-act story (`A SEED → A FOREST → THE ROOTS → THE MAP → THE TREE`). Match that gravitas elsewhere.
- *Editorial* — typographic confidence, generous space, serif headlines, monospace eyebrows, copy that reads like a magazine pull-quote, not marketing.
- *Organic* — the metaphor is a forest: roots, branches, forks, trails. Lean into woodcut warmth and analog texture, not cold tech-blue minimalism.

Emotional target: quiet authority. The user should feel they've found a tool made by someone who actually cares about how research feels.

### Aesthetic Direction

**Yes-references** (aesthetic ancestors): **Linear, Arc Browser, Raycast** — refined, opinionated, power-user apps where every interaction has been considered. Dense but breathable, keyboard-first, instant feel.

**Anti-references** (never confuse Trail with these):
- Generic SaaS / dashboard slop
- Gradient hero with three-icon feature row
- Purple-to-blue tech glow on dark
- "Build the future of X" headline structure
- Stock illustration of a person on a laptop with squiggles
- Glass morphism cards stacked over a blurred mesh

#### Theme

The marketing brand lives in **dark mode** (warm near-black `--landing-bg`, warm cream `--landing-ink ≈ #F6EFE1`, warm orange `--landing-ember` accent). The neutrals are tinted toward orange/ember — *not* cool blue-gray. Pure black and pure white never appear.

The product (extension panel, graph) supports both light and dark and ships ~40 user-selectable theme presets, so individual product surfaces must remain theme-neutral and read correctly on any of them. The default app theme leans dark for the same warm-editorial reason.

#### Typography

The landing uses a deliberate trio: **serif display** for headlines (clamped 36–68px, weight 400, tight `-0.025em` tracking), **monospace uppercase** for eyebrows (11px, `0.18em` tracking, ember color), and a soft cream body (`rgba(246,239,225,0.78)`). Keep this trio when extending the brand. Inside the extension, the shadcn defaults (Geist + Inter + Source Serif 4 + Fira Code) carry the load — keep type hierarchy crisp with at least a 1.25 ratio between steps and never converge to a flat scale.

Reflex-rejected fonts (Inter for headlines, Fraunces, Playfair, Plus Jakarta, etc.) are off-limits for *new* display work — Trail's serif voice should feel less templated than those, even if the body remains a workhorse like Source Serif 4.

#### Motion

**Instant, never bouncy.** Optimistic UI: state updates the moment the user acts; sync happens silently in the background. Animations decelerate (ease-out-quart/quint), never spring. The hero earns its scroll-driven cinematics; nothing else in the product gets to be that ambitious. Background sync errors are *silent* — no toasts, log silently, next tick recovers.

#### Surface rules (non-negotiable)

These already exist in user memory; they're load-bearing here too:
- **shadcn/ui is the only component vocabulary.** No bespoke buttons, cards, dialogs, alerts. Prefer shadcn primitives over raw Tailwind when an equivalent exists.
- **Never modify shadcn base files.** Compose in application code only.
- **No glassmorphism, no decorative blur, no AI palette** (cyan-on-dark, purple→blue gradients, neon accents).
- **Show all data.** Don't hide rows behind "view more" toggles when the user has the screen real estate.
- **Clear labels over icons.** Icons accompany words; they don't replace them.

### Design Principles

1. **Editorial over corporate.** Every screen should read like it was art-directed, not assembled. One bold typographic choice beats five competent ones.
2. **The forest is the brand.** Roots, branches, forks, trails — the metaphor extends into spacing rhythm, motion paths, and node iconography. Do not abandon it for a generic "minimalist" pose.
3. **Power-user respect.** Density is a feature. Show all data, support keyboard, never gate utility behind decoration. If a research analyst's eye can't land on what they need in one second, it's broken.
4. **Warm dark, not cold dark.** Neutrals tint toward ember/orange. Pure `#000` and pure `#fff` are banned. The night the user sees should feel like a desk lamp at 11pm, not a server-room dashboard.
5. **Instant, silent, optimistic.** No spinners where state can update immediately. No toast for every background event. Motion decelerates and resolves; it does not bounce or call attention to itself.
6. **No AI fingerprints.** Pre-flight every screen against the absolute bans: no border-left accent stripes, no gradient text, no glassmorphism, no nested cards, no centered hero with three feature cards underneath. If it could pass for a v0 / Lovable export, rebuild it.
